# 01 谁干什么：看、动、想

## 三层，各管一段

| 层 | 拿什么 | 出什么 | 多快跑一次 |
|---|---|---|---|
| 看（感知） | 光、声音、距离、姿态 | 距离多少厘米、目标在画面哪个位置、数到几个 | 每秒 10–60 次 |
| 动（执行） | 指令 | 电机转多快、舵机转多少度、屏幕显示什么 | 每秒 10–100 次 |
| 想（决策） | 目标 + 看到的东西 | 下一步做什么 | 每秒 0.5–10 次 |

## 一条公式决定一切

```
一圈要多快 = 看一次要多久 + 传过去要多久 + 动起来要多久
```

人慢走大约 1 米/秒，机器人的视野大概 0.5 米。所以：

- 超过 **200 毫秒**，跟起来就明显拖后腿；
- 超过 **1 秒**，基本跟不住，只能"停一下、看一次、再走"。

**所以"AI 放哪儿"不是喜好问题，是算出来的。**

## 三种分工，有一种是错的

| 怎么分工 | 结果 | 评价 |
|---|---|---|
| 看和动在机器人身上，想在云端 | 慢但可靠，适合"做任务" | 能用 |
| 看、动、想都在机器人身上 | 快、能边看边改、断网也能跑 | 最好 |
| 想在云端，却要它一帧一帧地控制 | 抖、丢目标、冲过头 | **错误做法** |

第三种最常见：把"AI 聪慧"当成"AI 能当控制器"。AI 擅长理解任务、临时取舍，不擅长在 50 毫秒内算左右轮差速。

## 要不要 Agent，用一句话测

**这件事能不能提前写成规则？**

- 能写成规则 → 在主控里写程序就行，不要 Agent。
  跟随、巡线、走固定距离、躲障碍、按颜色分拣，都属于这类。
- 写不成规则 → 才需要 Agent。
  比如"走到桌前停下、然后抓红块"、"路上有人挡就绕，绕不开就叫我"、"我说换目标就换"。

判断标准不是"项目高不高级"，是"规则覆盖得了吗"。

## 两层一起用怎么接

机器人身上一层管快反应（10–50 毫秒的控制环），云端一层管任务（秒级的计划和意外处理）：

```
云端 AI ──派任务──▶ 机器人上的程序 ──控制环──▶ 电机
   ▲                        │
   └──────事件/状态──────────┘
```

好处：网卡了不影响车稳；断网时车上程序还能自己安全停车。代价是要约定"发什么、回什么"（见 `05-协议模板.md`）。
