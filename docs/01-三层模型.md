# 01 三层模型：谁该干什么

## 分层

| 层 | 输入 | 输出 | 时间尺度 |
|---|---|---|---|
| 感知 | 光、声、距离、姿态 | 结构化数值（距离 cm、框坐标、计数） | 10–60 Hz |
| 执行 | 指令 | 电机占空比、舵机角、屏幕状态 | 10–100 Hz |
| 决策 | 目标 + 感知 + 历史 | 指令序列 | 0.5–10 Hz |

## 一条决定一切的公式

```
闭环周期 = 感知更新周期 + 链路延迟 + 执行响应
```

想让机器人"跟得住"，闭环周期必须显著小于目标运动的时间常数。人慢走约 1 m/s，机器人横向视野约 0.5 m，那么闭环周期超过 200 ms 就会明显滞后；超过 1 s 基本跟不住，只能"停顿—观察—再走"。

所以：**决策层放在哪里，不是偏好问题，是延迟预算问题。**

## 三种分工，只有一种是错的

| 分工 | 结果 | 评价 |
|---|---|---|
| 感知/执行在机上，决策在云端 | 慢但可靠，适合任务级编排 | 可用 |
| 感知/执行/决策全在机上 | 快、可闭环、断网可用 | 最优 |
| 决策在云端，却要求它做逐帧控制 | 抖、丢目标、过冲 | **反模式** |

第三种是最常见的错误：把"AI 很聪明"误解成"AI 可以当控制器"。Agent 的长处是理解任务和临场取舍，不是 50 ms 内算差速。

## 判断"要不要 Agent"

用一句话测：**这项需求能不能提前写成规则？**

- 能写成规则 → 控制器上写确定性程序（比例环、状态机），不要 Agent。跟随、巡线、定距、避障、按颜色分拣，都属于这类。
- 写不成规则 → 才需要 Agent。例如"跟到桌前停下，然后抓红块"、"途中有人挡就绕，绕不开就叫我"、"我说换目标就换"。

判据不是"这个项目高不高级"，是"规则覆盖得了吗"。

## 两级结构的写法

板载一层做反射（10–50 ms 的控制环），云端一层做任务（秒级的计划与异常处理）：

```
云端 Agent ──任务/策略──▶ 板载程序 ──控制环──▶ 电机
     ▲                        │
     └──────事件/状态──────────┘
```

好处：云端抖动不影响控制稳定性；断网时板载仍能安全停车。代价是要设计事件协议（见 `05-协议模板.md`）。
