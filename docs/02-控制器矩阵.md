# 02 控制器矩阵：把"能不能接"变成一张表

## 先看这一列

选型时只有一列是硬门槛：**控制器是否开放实时指令接口**。开放，Agent 可以靠近；不开放，Agent 只能待在链路另一端，隔着一层递字符串。其余（算力、系统、价格）都可以谈。

## 矩阵

| 控制器族 | 算力/系统 | 程序怎么进去 | 开放实时指令接口 | 可板载 Agent | 可达控制粒度 | 备注 |
|---|---|---|---|---|---|---|
| 单片机固件类（E6、C1、E3、M6 等） | MCU + 固件，无 OS | 电脑下载固件程序 | 否（公开资料无实时 API） | 否 | 宏动作 / 离散指令 | E6 已核对：屏幕 + RJ11 端口 + 固件程序；同族其他型号细节待实测 |
| 积木主控板（灵芯派类） | Linux 级 + 可跑 Node | 多平台编程 / 应用 | 是（工具层直连 IO） | 是 | 连续参数 / 闭环 | 官方演示过 OpenClaw 在该板上运行 |
| 通用 SBC（树莓派、Jetson 类） | Linux，算力可选 | 自写程序 | 是（需自己做驱动） | 是 | 闭环，上限最高 | 工程量最大：电机驱动、供电、结构都要自己解决 |
| MCU 开发板（ESP32-S3 类） | RTOS，百 KB 级内存 | 烧固件 | 是 | 可跑轻量 Agent | 闭环但受算力限制 | 适合"低功耗常在线"的小机器人 |
| PC / 手机 | 强算力 | 装应用 | 否（无机器人 IO） | 是（但不在机上） | 指令级 + 外部视觉 | 适合当"上级 Agent"，不适合当控制器 |

> 说明：标"待实测"的格子不是没结论，而是没有公开依据，需要自己用下面的探测法验证。欢迎提交实测结果。

## 给一台陌生控制器做 30 分钟探测

三个实验，按顺序做，任何一个通过都会改变结论：

1. **在线调试实验**：用厂商 IDE 连上，看除了"下载程序"是否还有"在线运行/实时监视/变量读写"。有，说明固件保留了调试通道，可能可以改造成指令入口。
2. **端口实验**：给控制器上电并连网（若有 WiFi），扫 22/23/80/8080/1883 等常见端口；有 HTTP 或 MQTT，说明厂商预留了数据通道。
3. **可替换实验**：查固件是否开源、是否可刷第三方固件、是否有串口烧录。能刷，就等于能换脑。

三个都不通，就不要在它身上做闭环，直接把"决策"放到链路另一端。

## 换脑的三个前置条件

决定"把控制器换掉"之前，确认这三件事，任何一件不成立都会让成本翻倍：

1. **接口兼容**：电机、舵机、传感器的物理接口和电气参数（电压、协议、线序）是否与新板一致。
2. **驱动兼容**：新板是否有对应电机驱动（减速电机看 H 桥，舵机看 PWM 通道数，编码器看正交解码）。
3. **供电**：电池电压、峰值电流、舵机堵转电流。算力板 + 多个舵机同时动作，是最容易翻车的地方。

## 迁移映射表（换脑时照着填）

| 原能力 | 原实现 | 新实现 | 状态 |
|---|---|---|---|
| 电机 M1/M2 正反转与调速 | 固件积木 | 新板 PWM + 方向脚 | 待填 |
| 舵机角度 | 固件积木 | PWM 定时器 + 角度表 | 待填 |
| 视觉模块读数 | 端口协议 | 同一协议 / 换直连摄像头 | 待填 |
| 超声测距 | 端口协议 | 同一协议 / 换 I2C 超声 | 待填 |
| 屏幕状态显示 | 控制器屏幕 | 新板屏幕 / 网页 | 待填 |

填完这张表，能不能换、要买什么，就一目了然了。
