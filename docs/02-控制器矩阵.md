# 02 控制器矩阵：中鸣控制器逐型号

## 先看这一列

选型时只有一列是硬门槛：**控制器是否开放实时指令接口**。开放，Agent 可以靠近；不开放，Agent 只能待在链路另一端，隔着一层递字符串。算力、屏幕、端口都可以谈，这一列不能。

## 这张表说明的两件事

1. **九款里只有两款能写"是"**：H-RCU 与灵芯派。其余七款都是"下载固件"模式。
2. **端口多寡改变能力上限，但改变不了模式**：E7 有 8 路电机端口，比 E6 的 4 路更能搭复杂机构；但只要固件只认"下载—运行"，Agent 依然只能待在链路另一端。

## 逐型号的选型建议

| 场景 | 建议 |
|---|---|
| 入门、点位有限的搭建 | M5：3 路传感器 + 2 路电机够用，点阵屏反馈直观 |
| 常规教学与竞赛 | E6 或 M6：8 路 P 口 / 5 路 P 口，传感器扩展余量足够 |
| 机构复杂、电机多 | E7：8 路通用 + 8 路电机，端口最富裕；屏幕大，现场调试方便 |
| 要脱机编程、不想带电脑 | C7：屏上就能拼图标逻辑 |
| 要跑 Agent、做闭环 | H-RCU 或灵芯派；E6/E7/M5/M6/E3 只能走外部链路 |

## 给陌生型号做 30 分钟探测

对 C1 这类没查到公开规格的，按顺序做三个实验，任何一个通过都会改变结论：

1. **在线调试**：用厂商 IDE 连上，看除"下载程序"外是否有"在线运行 / 实时监视 / 变量读写"。有，说明固件保留了调试通道，可能改造成指令入口。
2. **端口扇描**：若控制器能连 WiFi，扫 22 / 23 / 80 / 8080 / 1883；有 HTTP 或 MQTT，说明厂商预留了数据通道。
3. **可替换**：查固件是否开源、能否刷第三方固件、是否有串口烧录。能刷，就等于能换脑。

三个都不通，就不要在它身上做闭环，把决策放到链路另一端（见 `04-链路选型.md`）。

## 换脑的三个前置条件

决定"把控制器换掉"之前，确认这三件事，任何一件不成立都会让成本翻倍：

1. **接口兼容**：电机、舵机、传感器的物理接口与电气参数（电压、协议、线序）是否与新板一致。
2. **驱动兼容**：新板是否有对应驱动（减速电机看 H 桥，舵机看 PWM 通道数，编码器看正交解码）。
3. **供电**：电池电压、峰值电流、舵机堵转电流。算力板 + 多个舵机同时动作，是最容易翻车的地方。

## 中鸣 → 新板的迁移映射

| 原能力 | 中鸣上的实现 | 新板上的实现 | 状态 |
|---|---|---|---|
| 电机 M 口正反转与调速 | 固件积木 | PWM + 方向脚（H 桥） | 待填 |
| 舵机角度 | 固件积木 | PWM 定时器 + 角度表 | 待填 |
| AI 视觉模块读数 | P 口协议（K210 类模块） | 同一协议 / 换直连摄像头 | 待填 |
| 超声测距 | P 口协议 | 同一协议 / 换 I2C 超声 | 待填 |
| IoT 模块上下行 | P1 + MQTT 字符串 | 板载 MQTT 客户端 / 直接走本地网络 | 待填 |
| 屏幕状态显示 | 控制器屏幕 | 新板屏幕 / 网页界面 | 待填 |

填完这张表，能不能换、要买什么，就一目了然了。

## 和中鸣模块生态的关系

控制器决定了"能不能板载 Agent"，模块决定了"Agent 能拿到多少信息"。中鸣这两类外设值得先弄清：

- **IoT 模块（JMP-BE-9261）**：MQTT 字符串通道，2.4G WiFi，只能收发字符串，不执行动作。见 `04-链路选型.md`。
- **AI 视觉模块（JMP-BE-1742 / 1743 一类）**：K210 / Cortex-M7 板上跑识别，输出类别与坐标，不输出图像。见 `03-传感器矩阵.md`。

两者都不改变控制器的性质：模块再强，动作仍要控制器执行。
