# 06 复现清单：从 0 到 demo 的七步

每一步都有"通过标准"。没过标准不要进下一步，否则出了问题无法定位。

## Step 0 定目标

- 只做单一功能（跟随/巡线/定距）→ 目标就是"控制器上写确定性程序"，Agent 可省。
- 要做任务编排（多步、异常、自然语言）→ 才进入后面的 Agent 部分。

**通过标准**：能用一句话说清"agent 负责什么、控制器负责什么"，且两者不重叠。

## Step 1 选链路

按 `docs/04` 的决策树选一条，写进 README 的"本机配置"。

**通过标准**：能说出这条链路的延迟量级，且它小于你要求的最快控制周期。

## Step 2 接线

- [ ] 通信模块接在厂商指定端口（例如 P1），不与其他模块抢口
- [ ] 感知模块各自独占端口，记录端口号
- [ ] 电机/舵机接对应 M 口 / 舵机口，记录编号
- [ ] 供电单独核算：舵机堵转电流 × 数量

**通过标准**：上电后控制器屏幕/日志显示"网络已连接、平台已连接"。

## Step 3 最小闭环（先手动）

不接 Agent，先用 MQTT 客户端工具发一条 `STOP`。

**通过标准**：机器人在 2 秒内停车，且平台侧能看到消息记录。这一步通了，说明账号、topic、模块、控制器程序四件事全对。

## Step 4 机器人端三件事

1. 遥测：按 `docs/05` 格式上传感知数据（降采样、变化才发）。
2. 指令执行：比对字符串 → 执行宏动作 → 回 ACK。
3. 看门狗：3 秒无指令自动停车，本地计时，不依赖网络。

**通过标准**：拔掉网线/关掉热点，机器人 3 秒内停车；恢复网络后能继续响应。

## Step 5 桥接

用 `examples/bridge_skeleton.py` 起一个本地桥，暴露三个动作：

```bash
python examples/bridge_skeleton.py move F2
python examples/bridge_skeleton.py stop
python examples/bridge_skeleton.py look
```

**通过标准**：三条命令都能用，`look` 返回的 JSON 里有新鲜的遥测时间戳。

## Step 6 接 Agent

给 Agent 的工具集只放四个：

| 工具 | 参数 | 说明 |
|---|---|---|
| `robot_move` | `cmd`（枚举） | 执行宏动作，等 ACK |
| `robot_stop` | 无 | 立即停车，最高优先级 |
| `robot_servo` | `preset` | 舵机到预设角 |
| `robot_look` | 无 | 返回最近遥测（含时间戳与年龄） |

**通过标准**：Agent 能完成"看→走→看→停"的三步任务，且失败时能读到 `E:TIMEOUT` 之类事件而不是静默。

## Step 7 调参

| 参数 | 初值 | 调法 |
|---|---|---|
| 视觉死区 | ±20 像素 | 抖则加大，走偏则减小 |
| 转向增益 Kp | 0.3 | 从 0.1 起，观察到过冲就回调 |
| 目标框宽阈值 | 实测值 ±10% | 按实际跟随距离标定 |
| 宏动作时长 | 800–1000 ms | 超过链路延迟 2 倍才稳 |
| 看门狗超时 | 3000 ms | 必须 > 最长宏动作 |

**通过标准**：连续跑 3 分钟不丢目标、不停机、不撞墙。
