# 06 从 0 到 demo 的七步

每一步都有"过了才算"的标准。没过就别进下一步，否则出了问题没法定位。

## 第 0 步 定目标

- 只做单一功能（跟随 / 巡线 / 走固定距离）→ 目标就是"在主控里写程序"，AI 可以不要。
- 要做多步任务（带异常、要变通的）→ 才需要后面的 AI 部分。

**过关标准**：能用一句话说清"AI 负责什么、主控负责什么"，而且两者不重叠。

## 第 1 步 选链路

按 `docs/04` 的图选一条，写进自己的记录。

**过关标准**：能说出这条链路大概多快，而且比你要求的最快反应还快。

## 第 2 步 接线

- [ ] 通信模块插在主控指定的口（例如 P1），别和别的模块抢
- [ ] 每个传感器独占一个口，记下端口号
- [ ] 电机接 M 口、舵机接舵机口，记下编号
- [ ] 单独算供电：舵机堵转电流 × 个数

**过关标准**：上电后主控屏幕或日志显示"网络已连、平台已连"。

## 第 3 步 先用手机/电脑发一条"停"

不接 AI，先用 MQTT 客户端发一条 `STOP`。

**过关标准**：机器人 2 秒内停下，平台那边能看到这条消息。这一步过了，说明账号、topic、模块、主控程序四件事全对。

## 第 4 步 机器人端写三件事

1. 上报：按 `docs/05` 的格式发传感器数据（降频、变了才发）。
2. 执行：比对字符串 → 跑整套动作 → 回确认。
3. 自动停车：3 秒没收到指令就停，本地计时，不靠网络。

**过关标准**：拔网线或关热点，机器人 3 秒内停下；网络恢复后还能继续响应。

## 第 5 步 起一个本地桥

用 `examples/bridge_skeleton.py` 起桥，先暴露三个动作：

```bash
python examples/bridge_skeleton.py move F2
python examples/bridge_skeleton.py stop
python examples/bridge_skeleton.py look
```

**过关标准**：三条命令都能用，`look` 返回的数据里时间戳是新的。

## 第 6 步 接 AI

给 AI 的工具只放四个：

| 工具 | 参数 | 干什么 |
|---|---|---|
| `robot_move` | `cmd`（几个固定值） | 跑一套动作，等确认 |
| `robot_stop` | 无 | 立刻停车，优先级最高 |
| `robot_servo` | `preset` | 舵机到预设角度 |
| `robot_look` | 无 | 返回最近一次上报的数据（带时间戳） |

**过关标准**：AI 能完成"看 → 走 → 看 → 停"，失败时能读到 `E:TIMEOUT` 这类事件，而不是干等没反应。

## 第 7 步 调参

| 参数 | 初值 | 怎么调 |
|---|---|---|
| 视觉死区 | ±20 像素 | 抖就加大，走偏就减小 |
| 转向系数 Kp | 0.3 | 从 0.1 起，冲过头就回调 |
| 目标框宽阈值 | 实测值 ±10% | 按实际跟随距离标 |
| 单套动作时长 | 800–1000 毫秒 | 要超过链路延迟的 2 倍才稳 |
| 自动停车超时 | 3000 毫秒 | 必须比最长的动作还长 |

**过关标准**：连续跑 3 分钟，不丢目标、不停机、不撞墙。
